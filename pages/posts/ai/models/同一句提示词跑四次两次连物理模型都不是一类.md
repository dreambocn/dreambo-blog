# 同一句提示词跑四次，两次连物理模型都不是一类

一句话需求直接扔给 agent，和先让一个 agent 把它扩写成规格、再交给另一个 agent 实现——后者的效果好得多，这是我平时的体感。但有个地方一直说不通：扩写这件事 agent 自己也会做，我没给它任何新信息，只是把同样的需求换了个说法。信息量没变，结果凭什么差这么多？

所以我跑了个对照实验去验这件事。同一句提示词直接跑两次，两份产物一个用恒定减速度、一个用每帧乘性衰减，连物理模型属于哪一类都没统一——分歧程度超出我的预期。而更有用的一条结论是：扩写出来的规格如果不由人把控或二次编辑，最终结果仍然是抽奖，只是奖池换了。

## 我先给自己的四个解释

动手之前，我把能想到的机制列了出来：

**一、决策发生的位置不同。** "写个双人台球"里有大量未定项：什么玩法、怎么瞄准、犯规怎么罚、物理怎么算。这些必须被决定，否则代码写不出来。单阶段里，它们在生成过程中被就地、分散地一个个采样掉——写到第 40 行时决定一件事，写到第 200 行时决定另一件，两者之间没有一致性约束，因为它们从来没有作为一个整体被表述过。两阶段则强制把这些决策一次性做完、写下来。

**二、条件概率被锚定。** 实现 agent 的每个 token 都以完整规格为条件。`P(代码 | 详细规格)` 的分布比 `P(代码 | 一句话)` 尖锐得多，模型不必再把概率质量分配在"用户可能想要 A 还是 B"上。推论是：两阶段的输出应该**更稳定**，而不只是更好。

**三、注意力稀释。** 实现阶段上下文会被工具输出迅速灌满。如果原始需求只有一句话，几万 token 之后它的权重被稀释到接近噪声。一份结构化规格提供了足够长、可反复对齐的锚。

**四、无法反悔。** 自回归生成有强路径依赖，写下第一段实现之后，后续内容被前文锚定，即使模型"意识到"有更好的方案也倾向于自洽地错下去。而规格是一个**可以被丢弃的中间态**——看一眼说"不对，我不想要这个"然后重来，成本是零。

这四条听着都成立，但全是推断。所以去测。

## 实验设计

起点提示词完全相同，一句话：

```
做一个双人台球游戏的 HTML 页面。
```

- **A 路径**：直接交给实现 agent。跑 2 次（A1、A2）。
- **B 路径**：先由一个 agent 扩写成实现规格（明确禁止写代码），再交给另一个实现 agent。跑 2 次（B1、B2），两次扩写各自独立。

控制变量：全部 agent 同模型（Claude Sonnet）、同输出约束（单个自包含 HTML）、实现 agent 不知道自己在做对照实验。跑两轮而不是一轮，是因为按机制二的说法，两条路径的差异本身就体现在方差上——单点比不出方差。

|          | A1               | A2               | B1               | B2               |
| -------- | ---------------- | ---------------- | ---------------- | ---------------- |
| 实现     | 737 行 / 23.4 KB | 689 行 / 25.0 KB | 769 行 / 23.3 KB | 898 行 / 27.5 KB |
| 中间规格 | —                | —                | 26.0 KB          | 28.5 KB          |

一句 20 字的需求，被扩写成了将近 30 KB 的规格。

验证分三层：浏览器实际加载看渲染和 console 报错；静态提取物理常量；4 个互不知情的 agent 按统一检查表盲审代码，每条结论必须给行号。

## 结果一：A 路径两次做的根本不是同一个东西

|          | A1                   | A2                                                |
| -------- | -------------------- | ------------------------------------------------- |
| 摩擦模型 | 恒定减速度 340 px/s² | 每帧乘性衰减 ×0.986                               |
| 时间步长 | dt 裁剪到 0.033 s    | **完全没有 dt**，物理单位是"像素/帧"              |
| 犯规规则 | 只有母球落袋 1 种    | 落袋 / 空杆 / 首触错误组 / 清台后须首触黑八，4 种 |
| 犯规惩罚 | 对方获得手中球       | 仅换手，母球自动回位                              |
| 盲审评分 | 4 / 10               | 7 / 10                                            |

差异不在参数微调，而在物理模型的类型、规则体系的完整度、惩罚机制是否存在。A2 没有 dt，意味着球速随刷新率变化，120Hz 屏和 60Hz 屏上是两个游戏。A1 只有一条犯规规则，意味着母球空杆打偏不算犯规——八球规则里份量最重的那块整个缺失。

这一条把机制一验实了。如果决策是被整体表述过的，两次不至于在"物理模型属于哪一类"上分家。它们分家，恰恰因为这个决策从来没有被单独做过，只是在写到那一行时顺手选了一个。

## 结果二：B 路径确实收敛了

两次独立扩写，收敛到了同一组决策：美式八球、Canvas 2D、恒定减速度 400 px/s²、球半径 11px、袋口半径 22px、dt 裁剪 1/30 s、四类犯规、犯规给手中球且可自由摆放。

```
B1:  BALL_R=11  POCKET_R=22  FRICTION=400        RESTITUTION=0.92       MAX_PULL=150  MAX_SPEED=1400
B2:  BALL_R=11  POCKET_R=22  FRICTION_DECEL=400  RAIL_RESTITUTION=0.9   MAX_PULL=200  MAX_SHOT_SPEED=900
```

不是全都一样：B1 台面 800×400、B2 台面 900×450，出杆速度上限一个 1400 一个 900，子步一个动态一个固定 4 步。但这些差异不改变游戏是什么。分歧从"有没有手中球机制"降到了"子步是 4 步还是动态"。

## 结果三：平均分没有拉开，因为中间态没人管

|          | A1  | A2  | B1  | B2  |
| -------- | --- | --- | --- | --- |
| 盲审评分 | 4   | 7   | 7   | 5   |

A 组平均 5.5，B 组 6.0。A2 和 B1 同分，比 B2 还高。

这一轮里，扩写产物是直接喂给下一个 agent 的，中间没有人看。这也正是很多人实际的用法——两步都自动化，规格只是管道里的一段中间数据。

结果很清楚：**中间态不由人把控、不做二次编辑，最终结果仍然是抽奖。** B 组照样开出 5 分和 7 分，B2 那个"犯规杆落袋的球永久蒸发"一路畅通进了产物，中间没有任何环节拦得住它。

变的不是抽不抽奖，是奖池换了。A 路径在"有没有手中球机制、有没有 dt"这个层面抽——抽到 A1 那注基本不能用；B 路径把奖池收窄到"记账逻辑对不对、边界处理全不全"，里面每一注都是能跑的八球游戏，只是完成度不同。奖池小了、下限抬了，但它仍然是个奖池。

这也顺带打脸了机制二里"更稳定"那个推论：稳的是功能范围，不是质量。而且如果我只跑一轮、恰好抽到 A2 和 B2，会得出"扩写让结果变差"的结论。

## 结果四：只有 B 路径的实现者会报告"我替你决定了什么"

这条我事先没想到。

两个 B 实现 agent 交付时，都主动标注了自己做的越界解读：一个说明它对"开放桌面同杆进了双色球、之后再追溯归属"的处理是自己的解读，规格没覆盖；另一个说明它用"出杆瞬间的剩余球数快照"判断是否清台，并解释了为什么这么选。

两个 A 实现 agent 的交付说明里，一句这样的话都没有。

不是它们不诚实。是当需求只有一句话时，agent 无法区分"我在实现你的要求"和"我在替你做决定"——这两件事在它的输出里是同一件事。有了规格，"规格里写了的"和"规格里没写的"才成为两类东西，后者才有可能被报出来。

这其实是机制一更强的一个版本：显式化不只让决策更一致，还打开了一条汇报通道。一句话需求下，这条通道是关着的。对我来说这比代码质量更有用——我至少知道该去看哪几个地方。

## 结果五：30 KB 规格仍然有洞

B2 有个规格没覆盖的缺陷：犯规那一杆里顺带落袋的球，物理层已经把它移出球桌，但规则层只在"合法进球"分支里记账。这颗球从桌上永久消失，既不计入任何人的战绩也不放回球桌——那一组的"清台"条件可能因此永远达不成。

规格写了 28.5 KB、14 个章节、逐条列了非目标，还是没写"犯规杆打进的球怎么记账"。

另一处：B2 规格自己声明"不做响应式，画布固定尺寸"，实现却用了 `flex-wrap: wrap`。我在浏览器里实际打开时，窄一点的窗口下右侧面板直接掉到了球桌下面。有意思的是，审查这份代码的 agent 从 CSS 推断说"确认为横向两栏"——它读的是代码，我看的是渲染结果。

这两个洞性质不同，值得分开看：**规格里写错的、自相矛盾的，人扫一眼能发现；规格里漏写的，人扫一眼发现不了。** 所以就算我补上人工审阅那一步，B2 的球蒸发问题大概率还是会漏过去。规格化能减少隐式决策的数量，消不掉它们，而且因为规格看起来很完备，剩下那些更难被怀疑。

## 插曲：四个审查 agent 一致判反了同一条规则

四份实现在一条规则上分成两派：

- A1、A2：同一杆打进本组最后一球 + 8 号球 → 判**胜**
- B1、B2：同样情形 → 判**负**

四个盲审 agent 的判断高度一致：审 B 的两个都说这是缺陷（其中一个写"这是一个实质性规则 bug"），审 A 的两个都说处理正确（其中一个写"这个边界很多简化实现会做错，这里做对了"）。

查 WPA 世界标准八球规则：同一杆打进本组最后一球和 8 号球，**判负**。8 号球必须在清台之后单独一杆打进。

B 组是对的，A 组是错的，四个独立 agent 全把方向判反了。

这不是"多跑几个 agent 交叉验证"能解决的。它们共享同一套训练分布，错误是相关的不是独立的，四票一致只是把同一个先验重复了四遍。纠正它的是去查规则原文。

## 回头给那四个解释结账

**机制一（隐式决策 vs 显式决策）——成立，而且比我想的更强。** A 组两次连物理模型的类型都不同，这是决策从未被整体表述过的直接后果。额外收获是它还打开了"我替你决定了什么"的汇报通道。

**机制二（条件概率锚定 → 更稳定）——要改。** 稳定的是功能范围，不是质量。B 组两份的评分照样差 2 分。锚定消除的是"做什么"的歧义，消除不了"做得对不对"的波动。

**机制三（注意力稀释）——本次没测到。** 单文件任务，实现 agent 只调了 3 到 8 次工具，上下文根本没被灌满。这条要在长任务里才验得了，这次的数据说明不了任何事。

**机制四（可丢弃的中间态）——这一轮的配置里它压根没生效，而这就是结果三的成因。** 中间态只有在有人真的看一眼、改一笔的时候才谈得上"可丢弃"；没人管的时候，它退化成管道里的一段数据，两阶段随之退化成一次范围更小的抽奖。这条不算没测到——测出的是它缺席时长什么样。

## 我们能做的

1. **扩写不是解法，人卡在中间才是。** 规格如果不由人把控或二次编辑，它就只是管道里的一段中间数据，最终结果照样是抽奖，只是奖池小一点。这一轮的 B 组就是这么跑的，照样开出了 5 分和 7 分。

2. **单次对比不能得出结论。** 这次如果只跑一轮，有相当比例的抽样组合会给出方向相反的结论。判断一个提示词策略有没有用，至少两轮，看分布不是看单点。

3. **重点看实现 agent 报告的"我替你决定了什么"。** 这是规格化换来的唯一新增信息通道，比读全部代码性价比高得多。

4. **人工审阅能抓写错的，抓不住漏写的。** 看规格时不要只顺着读，要主动问"这里面没提到什么"。漏写的那部分会直接变成 bug，而且是最难被怀疑的那种。

5. **不要把 agent 当裁判。** agent 审 agent 能发现真 bug（这次确实抓到了手中球可以摆进袋口、死代码分支、UI 与内部状态不一致），但涉及外部事实标准时，多个 agent 的一致意见不增加可信度。该查文档还得查文档。

6. **简单任务别做两步。** 改常量、修 typo 这类无歧义任务，扩写是纯损耗还多一次幻觉机会。真正受益的是"未定项多、且这些未定项决定产品形态"的任务。
