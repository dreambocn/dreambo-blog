# 图片存储迁移

本次仅迁移笔记正文及其引用的图片附件，沿用 Typora 的 `picgo upload` 配置：Cloudflare R2 桶为 `blog-picture`，公开域名为 `https://picture.dreambo.cn`，对象命名规则为日期目录、原文件名和 MD5。站点头像、favicon、背景图及其他项目资源不参与迁移。迁移不修改 Typora 或 PicGo 配置，不删除本地图片或旧图床对象。

## 配置与运行

上传凭据在运行时从当前用户的 `.picgo\config.json` 读取，使用已安装的 `picgo-plugin-s3` 完成对象上传和地址格式化，不向项目写入密钥。运行前应已完成本机 PicGo 的 S3 配置。

以下命令适用于本机已有的 Node.js 26，复用当前代理环境变量。迁移命令不会作为站点构建的一部分执行。

```powershell
# 默认只扫描，不下载、上传或修改图片引用。
node --use-env-proxy scripts\migrate-images.mjs

# 执行迁移，支持断点恢复；并发数范围为 1 到 16。
node --use-env-proxy scripts\migrate-images.mjs --apply --concurrency=8

# 只复核已经上传但尚未验证的地址，不重复上传或重试不可达来源。
node --use-env-proxy scripts\migrate-images.mjs --apply --verify-only

# 如需重试某个来源域名，可限制处理范围。
node --use-env-proxy scripts\migrate-images.mjs --apply --only-host=s2.loli.net

# 运行图片引用解析测试。
node --test tests\image-references.test.mjs
```

可通过进程级环境变量 `PICGO_CONFIG` 指定配置文件，`BLOG_IMAGE_WORK` 指定独立的临时工作目录。当前任务默认工作目录为 `C:\Users\DreamBo\Documents\Codex\work\dreambo-blog\2026-10-17-r2-images`。

## 处理范围与校验

- 仅扫描 `pages\posts` 下 Markdown 笔记的图片、HTML `img` 和笔记封面字段；不扫描其他页面、站点配置或项目资源。跳过代码块、行内代码和已使用目标域名的地址。
- 同一来源只处理一次，并按内容哈希复用已验证结果。上传时保持图片字节不变。
- 公开地址返回有效图片且 SHA-256 与原始内容一致后，才替换对应图片引用；普通链接、代码演示与其余正文保持不变。
- 已上传但读取超时的对象保存原对象键与地址，恢复时只进行校验。缺失、无权限或无法访问的来源保留原引用。
- `checkpoint.json` 与下载缓存保存在临时工作目录，支持中断后恢复；不要在迁移运行中修改对应文章。

## 清单与交付

最终清单保存到 `outputs\image-migration-2026-10-17.json`，记录来源、新公开地址、对象键、哈希、原始引用和未完成原因。清单不包含存储凭据。

迁移后运行 `pnpm run build`，核对 SEO、站内链接和站点产物。仅本地源文件发生变更，网站仍需通过现有发布流程部署。
